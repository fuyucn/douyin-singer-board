# Signed updates

The macOS arm64 and Windows x64 signed installers use NSGo's Sparkle and WinSparkle integration. Enabled builds check periodically and offer installation and restart through the native updater. Settings → About → Check for Updates also requests a check; that action is blocked while listening, auto-syncing, or processing a platform operation. Approve installation when idle: the current queue, played list, and logs are session-only. Updates keep the app identity and data directory. Regular builds and Windows portable ZIPs do not opt into updates. Install the first updater-enabled build manually (on Windows use the NSIS setup, not a ZIP).

## Configure preview signing

1. From `nsgo-app` on a trusted machine, run `go tool nsgo keygen` privately. Keep the secret in a password manager; do not paste it in chat, print it in CI, or commit it. Keep the same key for this preview channel across releases.
2. In the release repository, protect the `nsgo-preview-signing` GitHub Actions environment with trusted refs and required reviewers. Set secret `NSGO_UPDATES_KEY` and variable `SONGBOARD_UPDATE_PUBLIC_KEY` to the corresponding values. For GitHub Releases, set `SONGBOARD_UPDATE_FEED` to `https://github.com/fuyucn/douyin-singer-board/releases/download/nsgo-preview/`. Packaging adds the `https://gh-proxy.com/` prefix to both appcast and installer download URLs, matching the legacy proxy format. An already-prefixed URL is also accepted. A custom HTTPS asset directory is used directly. The preview feed does not use the legacy application's `/releases/latest/` or `latest.json`.
3. Use a new `x.y.z-preview.N` in `nsgo.yaml` for each published version. Dispatch the **SongBoard signed preview updates** workflow on a trusted ref with a positive integer build number higher than every previously distributed updater-enabled build. The same number is used on both platforms and is independent of the display version. Reusing a build number can prevent installations; reusing a public version can overwrite a download referenced by older feeds.

The job is manual and uploads Actions artifacts; it cannot publish GitHub Releases. It verifies the appcast version, build, OS, URL, download length, checksum and Ed25519 signature before exporting release assets. The packaging command uses a temporary source copy and does not rewrite `nsgo.yaml`. Missing NSIS, key mismatch, and missing or invalid appcasts fail the build. On a trusted local release machine use `go run ./scripts/update-release -target macos_arm64 -build-number N -output dist/signed-preview-mac` from this directory with the same variables set. The Windows target is `windows_x64`. Use separate output directories for the two targets.

## Publish and verify previews

Use the dedicated **`nsgo-preview`** prerelease, never mark it latest, and never modify Tauri/NSH update assets. Upload both versioned installers and their checksums first, without replacing older installers. Then replace `appcast-macos_arm64.xml` and `appcast-windows_x64.xml` on that prerelease. For GitHub hosting, check that the GH Proxy URLs now serve the new build's appcasts and unmodified signed installers. Verify that an installed build N offers N+1, downloads and verifies the installer, and starts N+1 with its settings intact. Test Windows with an NSIS-installed copy, including a non-default writable install directory. Do not advance the feeds until both targets are ready.

The workflow's default Mac package is ad hoc signed, for controlled preview testing. Before public macOS distribution, build on a trusted machine with a Developer ID identity and notarization (set `SONGBOARD_MAC_SIGN_IDENTITY` and `SONGBOARD_MAC_NOTARY_PROFILE` for the local command). The installer is signed into the appcast after notarization; do not modify it after verification. Ed25519 update signing is separate from Apple notarization and Windows Authenticode. Windows SmartScreen and actual install/relaunch need device acceptance.

## Stable releases

Use a plain `x.y.z` version in `nsgo.yaml` and a reviewed source ref tagged `v<VERSION>`. Build with `go run ./scripts/update-release -channel stable -target macos_arm64 -build-number N -output dist/signed-stable-mac`; repeat with `windows_x64` and a separate output directory. Use a dedicated stable signing key, increasing build numbers, and `SONGBOARD_UPDATE_FEED=https://github.com/fuyucn/douyin-singer-board/releases/download/nsgo-stable/`. The same GH Proxy prefix and installer verification apply. Preview packages stay on their own feed. Do not publish test-key installers or ad hoc Mac builds as the stable release.

Publish the signed installers and the no-update Windows x64 portable ZIP with the versioned release. Put the exact signed installer bytes at their `nsgo-stable` download URLs before advancing both appcasts there. Keep both the versioned release and the `nsgo-stable` feed release out of GitHub's Latest slot while legacy clients still use that slot for `latest.json`. Verify proxied downloads and an actual install and upgrade on each OS before advancing the stable feed. Portable users replace their ZIP contents manually.
